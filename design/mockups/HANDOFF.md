`../tools/render.py` performs a geometric bounds check as part of every render: in both themes, every button, link, input, select, textarea, paragraph and heading on every artboard must lie inside its artboard's frame from `canvas.json`, or the script prints `BOUNDS <artboard> <theme>: <element>` and exits nonzero. The committed exports were produced by a passing run on 6 November 2026. The same run checks the canvas layout itself: no title or sticky note in `canvas.json` may overlap an artboard frame and no two frames may overlap (`LAYOUT …`, exit 1), because the renderer draws artboards only and would otherwise never see an annotation sitting on a board. This now checks the pinned intended-font render; painted glyph verification is recorded in `../exports/font-verification.json`. It does not prove the hosted artifact's exact font metrics.

**Repository refinement (#22).** The local renderer consumes `../system/`, including the SVG waiting-state ticks, placeholder contrast and table-date refinements documented in its handoff. These changes have not been republished to Claude. The version stamps above and in `canvas.json` identify the exported baseline and deliberately remain unchanged. Reconcile the local bundle refinements before the next artifact publication; do not overwrite them with the older embedded bundle. **Brand sheet caption (#8, PR #35).** After the owner's approval the sheet's caption was changed locally from "Design proposal • Owner approval pending (#8)" to "Design baseline • Owner approved 6 November 2026 (#8)" in `Brand-Sheet.dc.html`, and only the two Brand-Sheet renders were regenerated. Those two files were rendered with Chromium 153.0.8010.12 (the pinned 134.0.6998.35 could not be downloaded in that environment); every other export and `../exports/font-verification.json` remain from the Chromium 134 run, so a full regeneration on the pinned browser will change only those two files' anti-aliasing. This caption change is also not yet republished to Claude.

**Embedded design-system version.** The canvas copies the design system's `README.md`, `tokens.json`, `components/bundle.js` and `components/bundle.css` into `ds/oz-startup-brain/` at publish time; `canvas.json` records which artifact version they came from. Before version 14 that stamp still read `1793907664-c590` (the first copy) although the copied files had been refreshed on each republish: the files embedded in canvas version 12 were compared byte for byte with the committed version-8 export of `../system/` and were identical, so the stamp was stale metadata, not a divergent system. The stamp is now set from the version actually copied and must be updated on every re-export; the same comparison (`cmp` of the four files against `../system/`) is the check.

**Primary-action hierarchy (owner review on #17, recorded in #8).** Each real screen now has one intentional sage action: on the journey workspace it is the first next-step card's "Show supporting passage" (opening evidence beside the first action is the product's core move, O2); the other cards' inspect actions and "Export checklist" are secondary. SB3 Ask: "Start recording" (the persona's task); SB3 Route: the single card's inspect action; SB3 Summary: "Read summary", with export secondary. `NextStepCard` no longer hard-codes primary — the parent passes `emphasis`. A pressed starter task is a selected state (`ironbark-tint` with an `ironbark` border), not an action. SB5a/SB5b are comparison sheets of separate scenarios, so each `LimitPanel` keeps its own recovery action, as the review allowed. The mark's sage destination node is decorative and part of the logo.

**Voice disclosure (same review).** SB3 Ask and SB3 Transcript now say that the recording is sent to the transcription provider to make the transcript and that only the text the founder confirms is sent to the planner; the provider and its retention line are explicitly provisional until the provider is chosen, and `TranscriptReview` renders a visible placeholder if a consumer omits the disclosure. After the owner's density critique on #20 the Ask disclosure is a two-row labelled list ("Audio goes to" / "The planner gets") and the transcript line is one sentence, so the facts stay visible before recording without competing with the input.

**Density and balance (owner critique on #20, design critique not a usability finding).** The workspace's evidence rail was widened (cards capped at 688px, rail flex 2 from 400px) so dates, links and metadata are no longer cramped, and the prerequisite map stacks its drawing above its list in rails narrower than two 300px columns, with the drawing capped at 320px. The original #20 evidence used fallback fonts. Issue #22 regenerates these exports with verified intended fonts and records its critique, fixes and reinspection in [the visual review](../reviews/issue-22-fonts.md). This completes the builder typography/polish pass for that bounded change; independent review and owner design approval (#8) remain separate.

Every program, round, source and person on these boards is a labelled fictional fixture. The `.dc.html` files mount the design system's components with `<x-import>`; `../tools/render.py` reproduces the PNGs with a minimal stand-in for the canvas runtime (pinned local intended fonts) and resolves uploaded canvas assets through `assets.json`, failing on any unmapped image.

The low-fidelity paper SVGs in `docs/ux/` remain the printed-session versions; these are the higher-fidelity source. Observations in the review report about these boards are simulated design critiques, not user research.

## Visual quality requirement for future changes

Apply the [standing visual quality standard](../../docs/ux/visual-quality.md) before completing any revision or frontend implementation based on this handoff. Identify the largest visual weaknesses, fix material issues, and inspect the revised render; include before/after evidence and the reviewed version. Check intended fonts, relevant themes and actual placements, not only fallback-font geometry. This requirement does not change the artifact version; the explicit owner approval above is separate from implementation polish, accessibility evidence and user research.
